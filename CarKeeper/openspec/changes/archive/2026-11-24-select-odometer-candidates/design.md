# Design

## Context

参见 [proposal.md](proposal.md)。`interpretOdometer` 已将多个识别数字归为 `ambiguous`，但只保留原始字符串，丢失了每个数字的可信度和解析结果。`ResultView` 对此只显示警告；单个高可信度候选已有可修改、校验和采用的流程。

## Goals / Non-Goals

**Goals:** 在不自动猜测总里程的前提下，让用户核对并选择多个 OCR 读数，复用现有表单确认和取消流程。

**Non-Goals:** 不改变 OCR 模型、单个数字的可信度规则、里程数据格式或隐私边界；不推断数字在照片上的位置或含义。

## Decisions

### 保留每个识别读数的解析结果

歧义结果按识别顺序携带每个读数的原始文本、可信度及可选的安全整数值，复用现有数字解析规则：千分位可转为整数，小数和超出安全整数范围的值不能直接采用。分别标记低于现有阈值的整数；不将相邻数字拼接或自动推荐最大值。

相比 UI 重新解析字符串或仅传递整数，携带结构化结果可保持显示、校验和可信度一致，并保留小数或无效读数供用户辨认。单个低可信度结果及仅有小数的现有处理保持不变。

### 选择与采用分开

多数字结果显示适合手机操作的可选整数列表，初始不选择；小数及无效读数可见但不可选。选择整数后填入确认框，允许编辑，复用 `parseOdometer` 校验和现有“采用”流程；选择本身不修改表单。识别结果说明总里程与小计、续航的区别，并突出低可信度警告。

相比点击即填入表单，两步操作保留检查和修正机会。重新识别、换图或关闭时清除选择，继续使用现有异步取消机制，不能让过期结果覆盖新状态。

### 验证

单元测试覆盖整数与小数混合、千分位、低可信度、超出安全范围及不拼接；浏览器测试覆盖选择、编辑、采用、取消、重识别和换图，验证原有表单内容保持及不同记录表单一致。覆盖手机视口和键盘操作，并运行现有单候选、离线与识别相关回归测试。

## Risks / Trade-offs

- [OCR 将一个读数拆成多个数字或识别错误] → 不自动拼接或选取，提示对照照片，可编辑或重新识别。
- [低可信度数字可能错误] → 明确标记并要求用户检查、主动采用。
- [长读数、小数或超范围数字] → 显示原文，不允许非法值直接采用，并校验编辑后的输入。
- [旧选择或异步结果残留] → 在换图、重识别和关闭时重置状态并测试。

## Migration Plan

无数据迁移。随现有 Pages 工作流部署，用户按 PWA 提示更新；需要回滚时发布旧版本，不清除站点数据。
