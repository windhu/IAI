# Design

## Context

动机见 [proposal.md](proposal.md)。已检查项目结构及既有规格：没有应用源码、依赖清单、业务测试或已有能力可复用，需从零搭建。用户已选择 Android 优先、链接及桌面入口、本地存储、本机 OCR、无账号和云同步。

这是跨界面、持久化、资源缓存及图片处理的新架构，包含新依赖和备份事务设计，因此需要设计文档。第一版按单车、公里、人民币处理，是可审阅的范围假设，而非已存在的数据模型。

## Goals / Non-Goals

**Goals:**

- 将记录存储与 OCR 解耦，使识别失败、模型未准备好或断网不阻断手工记录。
- 用统一数据校验覆盖表单和备份恢复，避免两个入口接受不同的非法数据。
- 只在持久化提交成功后报告成功；恢复失败不损坏原记录。
- 构建可由 HTTPS 静态站点分发、无需原生 SDK 的应用。

**Non-Goals:**

- 不通过远端 OCR 补救本地识别失败，不把照片永久存储为记录附件。
- 不根据照片自动判断所有仪表盘语义，不自动保存识别结果。
- 不实现云端兜底备份、多车模型、油耗算法或账号基础设施。

## Decisions

### 1. React + TypeScript + Vite，静态部署

以 React 和 TypeScript 组织移动界面，Vite 构建静态产物，使用轻量 CSS 而非大型 UI 框架。首页提供“记保养”“记加油”，并能进入历史及备份；表单内提供手工里程与照片识别入口。不依赖服务端路由，避免静态托管刷新子路径失败。

采用 `vite-plugin-pwa` 配置 manifest、图标和 service worker，更新方式为提示用户操作，而非自动刷新。原生 Expo 路线虽然可生成 APK，但引入构建及分发流程；当前确认的链接分发需求不需要它。

项目无现成测试工具，实施时建立 Vitest 核心逻辑测试及 Playwright 浏览器行为测试；不在规划阶段生成配置或安装包。

### 2. IndexedDB 保存单车记录

使用 IndexedDB 及 `idb` 的事务封装，不把记录放在只适合少量字符串的 localStorage 中。定义以记录类型区分的联合模型：

| 字段 | 约定 |
| --- | --- |
| `id` | 本机生成的唯一字符串，编辑和恢复时保持不变 |
| `type` | `maintenance` 或 `fuel` |
| `date` | 本地事件日期 `YYYY-MM-DD`，不做 UTC 日期转换 |
| `odometerKm` | 非负安全整数 |
| `amountFen` | 人民币整数分；保养可省略且允许零，加油必填且大于零 |
| `notes` | 可选纯文本 |
| `createdAt` / `updatedAt` | 有效 ISO 时间戳；同日按创建时间及标识稳定排序 |
| `items` | 保养必填的非空项目字符串列表，包含预设或自定义项目 |
| `volumeMl` | 加油可选的正安全整数，以毫升保存输入的升数 |

从十进制输入字符串准确转换分和毫升，避免浮点乘法导致金额漂移；拒绝非法、非有限值或超出安全整数范围的值。复用同一校验层处理表单和备份。保养费用同样至多两位小数。

每次新增、编辑、删除等待事务提交，再刷新历史或显示成功。读取失败显示错误和重试入口，不以空数组替代。检查按日期排列的相邻里程走势，矛盾时给核对提示，不强制单调递增，允许补录旧记录。多标签页的备份替换及写入依靠数据库事务串行化，成功后重新读取，不使用过期内存快照覆盖数据库。

### 3. 本机 OCR：裁剪优先，确认后填入

选择 Tesseract.js 的浏览器 Web Worker 和 WASM 路线，图片通过浏览器选择器取得，可请求后置相机拍照，也保留相册入口。使用本机画布处理方向、裁剪和适度缩放，避免把高分辨率整张照片直接送入识别。只加载识别数字及 `ODO`、`km` 等必要文本的模型。

按所选依赖版本自托管 worker、兼容的 core/WASM 文件和语言模型，通过显式资源路径禁用默认 CDN 加载。Tesseract.js 官方 [本地资源配置说明](https://github.com/naptha/tesseract.js/blob/master/docs/local-installation.md) 支持这些路径；具体发布文件及许可证在依赖落地时核对，不照抄旧文档中的版本。

保留 OCR 文本的数字边界和可信度，不能把多个数字拼接、将小计小数去掉小数点、取最大值或把失败值变成零。唯一可解析且达到评估后确定的可信度门槛的整数作为候选；歧义或低可信度转为明确提示。门槛不是“总里程语义正确”的保证，任何候选都要求用户核对裁剪图和总里程含义后采用。

```text
photo --> crop --> local worker --> candidate --> confirm --> form
            |            |
            v            v
          cancel       error --> recrop / retry / manual input
```

采用任务标识忽略取消或更换图片后的迟到结果；取消或离开页面时终止任务、清理 worker 和临时对象 URL。识别期间展示进度，保留取消及手输路径。测试实际清晰仪表盘图片的已知总里程，不能只验证“返回了数字”；另测多数字、反光、模糊和取消。

### 4. 分离基础离线缓存与 OCR 准备

基础应用及界面资源预缓存，OCR 资源首次使用时按需下载，并显示独立准备进度。所有路径按应用部署基路径生成，保证子目录托管时 worker、模型和 manifest 仍可加载。

OCR 资源集按版本缓存，只有所需资源全部存在且能初始化时标记就绪。每次重新使用前重新检查，不仅依赖曾经写入的就绪标志，因为浏览器可能回收缓存。缺失时在线重试下载，离线则提示手输；不调用远端识别。应用代码动态加载时也属于该资源集。

新 service worker 在后台准备更新，但由用户选择刷新时激活，编辑中不强制刷新。清理旧缓存只针对本应用版本化的缓存名称，不清空 IndexedDB。基础离线与 OCR 离线分别验证，不能仅靠网络连接状态判断资源是否就绪。

### 5. JSON 备份与原子整库替换

备份包包含 `format: "carkeeper-backup"`、`version: 1`、`exportedAt`、`units: { distance: "km", currency: "CNY", volume: "L" }` 和 `records`。包的展示单位与模型中的整数分、毫升约定一起固定为版本 1 的格式，避免读取者误将 `amountFen` 当作元。导出使用一致的只读事务快照，不包含图片或未保存的表单。

恢复先读取并完整校验包及全部记录，包括重复标识、类型对应字段、日期、时间戳和数值范围；未知格式版本和单位直接拒绝，不猜测迁移。预览条数并说明覆盖，建议先导出当前数据。用户确认后，在单个读写事务内清空记录存储并写入有效备份；任何失败都使整个事务回滚。第一版不做合并，避免标识冲突、重复加油记录或静默覆盖。

文件以纯文本处理，备注和项目显示为文本，不作为 HTML。导出失败不生成成功形态的空文件。恢复后保留标识和创建时间，因此重新打开及同日排序一致。

### 6. 隐私与错误呈现

运行时没有 API、账号、第三方分析或记录上传。应用与 OCR 资源由同一静态站点提供；网络只承载静态资源下载。存储操作、图片解码、资源加载与恢复的错误映射为具体中文提示，避免静默兜底。备份页面明确说明浏览器清理风险和 JSON 文件未加密。

## Risks / Trade-offs

- 数字仪表、七段数码屏和反光可能影响 Tesseract.js 识别效果 -> 实际图片验证、裁剪、保守候选和用户确认；若已知清晰图片仍无法输出正确候选，任务保持未完成，不以手输回退宣称 OCR 已通过。
- OCR 首次下载较大，低端手机处理慢 -> 动态加载、图片缩放、独立就绪状态和可取消任务；记录真实资源大小、识别耗时和设备信息，不承诺尚未测得的准确率。
- 浏览器可能回收本地数据库或缓存 -> 显示备份说明，提供导出恢复，检查缓存实际可用性；持久化存储申请可作为最佳努力，不声称永不丢失。
- 不同浏览器或站点域名的数据不自动共享 -> Android Chrome 作为验收基线，部署保持稳定 origin，换浏览器或域名依靠备份恢复。
- 浏览器安装和相机入口行为不同 -> 提供文字安装指引、相册及手输入口；真机验证，不用桌面模拟替代全部验收。
- 整库恢复会覆盖当前记录 -> 校验、预览、明确确认、导出建议和单事务回滚。

## Migration Plan

1. 当前没有业务数据，无既有模型迁移；初始 IndexedDB schema 和备份格式均从版本 1 开始。
2. 构建后在固定 HTTPS 静态 origin 部署应用、图标、worker、WASM 和语言模型，不在此阶段选定或创建云资源。
3. 发布前完成自动化验证，并在 Android Chrome 检查链接访问、桌面入口、离线重启、记录持久化、备份恢复和本机 OCR。
4. 更新仅使用兼容版本 1 数据格式的产物。回滚静态产物时保持同一 origin 和用户数据库，不以清理站点数据作为回滚手段。

## Open Questions

- 用户将选择哪个静态托管平台及链接名称；只要支持 HTTPS 和相应静态资源，选择不改变架构与任务边界。
- 可获得哪些允许本机测试的仪表盘照片和 Android 真机；实施中记录测试图片对应的正确读数和设备性能，不上传个人照片或将未经许可的素材纳入仓库。
