# Proposal

## Why

车主需要在手机上快速记录保养与加油时的日期、总里程和费用，避免信息散落或遗忘。通过链接分发的轻量应用可以满足 Android 优先的使用需求，无需安装 Android Studio 或维护原生安装包。

## What Changes

- 新建 Android 优先、中文界面的 PWA，支持链接访问、添加桌面入口和完成首次缓存后的离线记录。
- 提供保养与加油两个快捷入口，支持新增、查看、修改、删除，并将记录持久化在当前设备。
- 保养记录包含日期、总里程、多选保养项目、可选费用和备注；加油记录包含日期、总里程、金额、可选升数和备注。
- 通过拍摄或选择仪表盘照片，在本机识别裁剪区域中的总里程；候选值必须经用户确认，失败或歧义时支持手输，不自动保存。
- 提供带格式版本的备份导出及经过校验、预览和确认的恢复，明确提示本地数据可能因浏览器清理而丢失。
- 第一版按单车、公里、人民币规划。无账号、云同步、照片上传或服务端 OCR；不包含油耗统计、保养提醒、多车管理和应用商店发布。

## Capabilities

### New Capabilities

- `vehicle-records`: 保养和加油记录的字段、校验、历史管理及本机持久化。
- `odometer-recognition`: 仪表盘照片的本机识别、总里程确认及手工输入回退。
- `offline-pwa`: Android 手机访问、桌面安装引导、离线运行与资源就绪状态。
- `local-backup`: 本地记录的版本化导出、验证、预览及安全恢复。

### Modified Capabilities

无。项目目前没有已有功能规格。

## Impact

- 当前项目仅有 OpenSpec 和开发辅助目录，没有应用源码、依赖清单或现成测试；这是从零新增应用，不修改既有业务行为。
- 将新增前端应用、IndexedDB 存储、PWA 资源缓存、本机 OCR 依赖和针对核心行为的测试。
- 部署只需要 HTTPS 静态托管，不新增业务服务器、远端数据库或密钥。
- OCR 模型及运行资源需要自托管和缓存；实际仪表盘识别质量与低端 Android 性能需要在实施中验证，不能以通用文字识别能力代替总里程验证。
