# Design

## Context

当前 `.main` 的最大宽度是 560px、两侧内边距是 16px；底部导航则横跨视口。各页面共用主容器，表单和历史内容均由路由组件渲染。需求见 [proposal.md](proposal.md) 和 [规格](specs/responsive-layout/spec.md)。

## Goals / Non-Goals

**Goals:** 让内容宽度随视口变化，并在文字放大后保持布局可操作。

**Non-Goals:** 不重新设计记录流程，不通过整体缩放页面改变显示比例，不更改导航或存储语义。

## Decisions

### 容器与表单

手机端将主容器左右内边距调整为 12px，同时考虑横屏安全区域；平板及以上逐步扩大容器，桌面最大宽度建议 960px。首页和历史页面使用较宽容器，新增、编辑及备份等表单区域限制在 720px 内并居中。

选择按页面限制表单而非全站统一 720px，是为了扩大首页和历史的有效空间，同时避免输入框过长。不得固定高度或依赖隐藏横向溢出来掩盖内容裁切；长文字和控件应允许换行。

### 字体与交互

正文按浏览器默认字体的 1.0625 倍设置，默认 16px 时为 17px；不固定根字号，以保留用户字体偏好。审查现有 `rem` 标题、提示文字和按钮的继承关系，确保提示可读且主要控件高度至少 44px。底部导航在文字放大时允许换行，并根据实际高度预留内容空间，避免遮挡页面末尾。

备选的 `transform: scale()` 或固定大字号会造成布局尺寸和真实点击区域不一致，或忽略用户字体设置，因此不采用。

### 验证

在 360、390、768、1024 和 1440 CSS px 下检查首页、记录表单、历史、备份及底部导航；覆盖默认字体和 200% 默认字体，并实际检查元素边界，而非仅依赖 `scrollWidth`（现有页面隐藏横向溢出）。确认记录、备份及离线启动行为不变。

## Risks / Trade-offs

- [大字体使导航或表单换行] → 允许高度增长并预留底部空间；验证键盘和触控操作。
- [宽屏输入框过长] → 对表单单独限制宽度；使用视觉检查确认页面平衡。
- [隐藏横向溢出掩盖裁切] → 测试实际内容边界和可见性，不只检测滚动条。

## Migration Plan

无需数据迁移。按现有 Pages 工作流构建发布；PWA 用户按现有更新提示更新。必要时在同一网址回滚构建产物。
