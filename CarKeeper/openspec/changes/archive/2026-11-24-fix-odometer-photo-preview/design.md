# Design

## Context

参见 [proposal.md](proposal.md)。当前 `decodeImage` 使用 `createImageBitmap` 解码照片用于 OCR；裁剪组件则通过原始文件的 object URL 在 `<img>` 中再次加载。`<img>` 失败不会进入错误状态，现有测试只确认裁剪容器可见，不检查图像实际绘制。

手机报告的表现与预览加载失败一致，但尚未在小米真机上确认底层原因；实现及验收不能把模拟结果当成真机修复证明。

## Goals / Non-Goals

**Goals:** 从已解码的照片显示预览，保证框选和 OCR 使用同一方向，并明确处理预览失败。

**Non-Goals:** 不改变 OCR 模型、可信度规则、记录存储或照片隐私边界；不承诺浏览器支持其自身无法解码的格式。

## Decisions

### 使用已解码图片渲染预览

裁剪组件直接将已按 EXIF 方向解码的 `ImageBitmap` 绘制到画布，画布保留原始宽高比，并为辅助技术提供照片描述。显示用画布限制最长边为 1600 像素且不放大小图，避免大照片占用过多额外内存；OCR 继续使用原始解码图像和归一化裁剪坐标，不以缩略预览替代识别图像。

相比继续对原文件创建 object URL 再由 `<img>` 解码，画布复用已有像素，避免预览依赖第二次独立加载。绘制失败、无法获取 2D 上下文或尺寸无效必须显式报错；不能仅显示空容器。保持原始比例和方向，以便裁剪框坐标映射到识别图像。

### 状态与生命周期

选图后先解码并绘制，只有当前照片的预览实际完成才进入可裁剪、可识别状态。绘制失败时显示可理解的错误，并保留重新选择及手动输入入口；更换照片、取消和卸载时用现有 token 忽略过期结果，并释放 ImageBitmap、画布及其他临时资源。任何异步失败都不得被静默当成成功。

### 验证

浏览器测试必须检查预览的真实像素及非零尺寸，而非仅检查容器存在。覆盖 JPEG 和带 EXIF 旋转的图片、框选与 OCR 裁剪坐标、重新选图、预览绘制失败、关闭期间异步完成，以及正常离线和识别路径。用设备模拟验证布局和触摸；另在用户的小米浏览器真机上重复原始操作，记录浏览器版本和结果，避免将模拟器通过当作真机通过。

## Risks / Trade-offs

- [画布绘制或内存分配失败] → 限制预览尺寸，检测失败并提示换图或手输。
- [图像方向或缩放导致识别区域偏移] → 使用同一解码图像和比例坐标，测试 EXIF 方向及实际裁剪像素。
- [不同浏览器仍有解码兼容性差异] → 明确显示解码错误；真机验证前不宣称小米浏览器已修复。
- [切换图片或离开页面时旧结果回写] → 用 token 校验每个异步阶段，并测试资源释放。

## Migration Plan

无数据迁移。按现有 Pages 工作流构建部署，用户按 PWA 更新提示更新；如出现回归，在同一网址回滚版本，不清除站点数据。
