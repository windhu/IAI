# 爱车记录 使用说明

## 适用范围

- **单车**：第一版只记录一辆车，不区分车辆。
- **单位**：里程为**公里**（整数），金额为**人民币元**（最多两位小数），加油量为**升**（最多三位小数）。
- **只存本机**：记录保存在当前手机浏览器的本地数据库中。没有账号、没有云同步，记录、照片和备份都不会上传。
- 换手机、换浏览器或清除浏览器数据后，记录不会自动出现，需要用备份文件恢复（见“备份与恢复”）。
- **品牌标识**：首页标题旁和底部会显示“峰哥出品”。每次冷启动时，应用还会短暂显示带品牌标识的启动画面；页面准备好后自动淡出，轻点即可跳过。这是应用内画面，不会替换 Android 系统启动画面或桌面图标。

## 记保养

首页点 **记保养**。

| 字段 | 是否必填 | 说明 |
| --- | --- | --- |
| 日期 | 必填 | 默认今天，可改为任意过去日期（可补录旧记录） |
| 总里程（公里） | 必填 | 不含小数的非负整数，可手动输入或点“拍照识别” |
| 保养项目（可多选） | 至少一项 | 预设：更换机油、更换机滤、更换空气滤芯、更换空调滤芯、更换刹车片、更换刹车油、更换轮胎、更换火花塞、更换蓄电池；其他项目在下方输入框填写后点“添加” |
| 费用（元，可选） | 可选 | 可以为 0，最多两位小数 |
| 备注（可选） | 可选 | 任意文字 |

## 记加油

首页点 **记加油**。

| 字段 | 是否必填 | 说明 |
| --- | --- | --- |
| 日期 | 必填 | 默认今天 |
| 总里程（公里） | 必填 | 不含小数的非负整数，可手动输入或点“拍照识别” |
| 金额（元） | 必填 | 大于 0，最多两位小数 |
| 加油量（升，可选） | 可选 | 大于 0，最多三位小数；不填也能保存。第一版不计算油耗 |
| 备注（可选） | 可选 | 任意文字 |

## 保存规则

- 填写有误时，对应字段下方会显示原因，已填内容不会丢失。
- 只有真正写入手机后才会显示“已保存记录”。如果手机存储空间不足或存储不可用，会提示“记录未保存”，表单内容保留，可以稍后重试。
- **里程核对**：如果新记录的里程比更早日期的记录还低（或比更晚日期的记录还高），会提示核对。确认无误后点“仍然保存”即可。补录早期日期、较低里程的记录不会被拒绝。

## 历史记录

- 按日期从新到旧排列；同一天的记录按录入先后排列，顺序固定。
- 点一条记录查看详情，可 **编辑** 或 **删除**。删除前需再次确认，删除后无法撤销。

## 备份与恢复

底部导航点 **备份**。

**为什么要备份**：记录只保存在这台手机的浏览器里。清除浏览器数据、卸载浏览器、更换手机或换用其他浏览器，都可能看不到原来的记录。建议定期导出备份，并把文件保存到网盘、电脑等安全位置。

**导出**：点“导出备份文件”，会下载一个 `carkeeper-backup-年月日-时分.json` 文件，包含全部保养和加油记录（不包含照片）。页面会显示导出了多少条。

> 备份文件是**未加密**的纯文本，任何拿到文件的人都能看到你的记录，请自行妥善保管。

**恢复**：点“选择备份文件”并选中之前导出的文件。

1. 系统会先完整检查文件：格式、版本、单位、每条记录的内容以及是否有重复记录。有问题会说明原因，本机记录不做任何修改。
2. 检查通过后显示备份里的保养、加油条数，以及本机当前条数。
3. 恢复是**整体替换**：本机现有记录会被备份内容替换，不会合并。如需保留当前数据，请先导出一份。如果备份里没有任何记录，会特别提示“恢复后本机所有记录将被清空”。
4. 点“确认恢复”才会执行；点“取消”不做任何修改。
5. 恢复要么全部成功，要么完全不生效。中途失败（例如存储空间不足）时，本机原有记录保持不变，并提示失败原因。

导出和恢复都在手机本机完成，断网时也可以使用。

## 拍照识别总里程

在记保养或记加油的“总里程”旁点 **拍照识别**。识别只是**辅助填写**，任何结果都要你核对确认后才会填入，并且不会自动保存记录。

### 操作步骤

1. 点 **拍照**（后置相机）或 **从相册选择**。如果相机打不开（没有授权或浏览器不支持），用相册或直接手动输入。
2. 在照片上**拖动框选**，只框住总里程（ODO）那一串数字，尽量不要框进小计里程（TRIP）、续航、时间、温度等其他数字。框得越紧越准。
3. 点 **识别所选区域**。识别在手机上完成，照片不会上传，也不会保存到记录或备份中。识别期间可以随时取消。
4. 根据结果：
   - **给出识别结果**：核对它确实是总里程（不是小计里程或续航），可以直接修改，然后点 **采用**，数字才会填进表单。
   - **可信度过低 / 识别到多个数字 / 只识别到带小数的数字 / 未能识别出数字**：不会给出任何数值，以免填错。请重新框选、换一张照片，或点 **改为手动输入**。
5. 采用后照样可以修改总里程，最后点保存。

### 首次准备

- 识别需要约 **6.6 MB** 的本机识别资源（识别程序约 0.1 MB、识别引擎约 3.7 MB、文字模型约 2.8 MB），**只需下载一次**。
- 第一次识别时会自动下载并显示进度；也可以在首页“使用与离线”中点 **下载** 提前准备。
- 显示“拍照识别资源已就绪”后，断网也能识别。如果资源还没下载好就断网，或浏览器清理了这些资源，识别会提示暂不可用，此时手动输入即可，不影响保存。

### 实测效果与限制

识别引擎是通用文字识别（Tesseract），并非专门针对仪表盘训练。我们用 15 个取自公开授权照片的仪表盘裁剪样本（真实读数已人工核对）在电脑版 Chrome 中测试了完整流程，结果如下：

| 类型 | 样本 | 结果 |
| --- | --- | --- |
| 清晰的液晶数字屏（大字） | 2 | 1 个给出正确结果；1 个（夜间、数字很小）可信度不足被拒绝 |
| 七段数码屏 | 4 | 全部被拒绝（读不准或拆成多个数字） |
| 带小数位的总里程（如 173386.2） | 2 | 全部被拒绝（设计如此：不会去掉小数点猜测整数） |
| 机械滚轮 + 反光 | 3 | 全部被拒绝 |
| 模糊 | 1 | 被拒绝 |
| 框选了多个数字 | 3 | 全部被拒绝 |
| **合计** | **15** | **正确 1，拒绝 14，错误 0** |

- 给出结果的门槛是可信度 **85%**。测试中出现过的错误读数可信度最高为 78%（反光遮住首位数字，150000 被读成 50000），因此门槛设在其之上，宁可拒绝也不给出错误数字。
- 实际可用性取决于你的仪表盘：**大字、高对比度、无反光的数字屏**最容易成功；七段数码屏、带小数位的里程、机械滚轮、反光和模糊照片大多会被拒绝，需要手动输入。
- 在电脑版 Chrome 中每次识别（含启动识别引擎）约 0.5–2.6 秒（中位数约 0.9 秒）。**尚未在真实 Android 手机上测量**，低端手机会更慢；识别期间可随时取消。
- 以上不是准确率承诺。识别结果一律需要你核对后再采用。

### 用自己的照片评估（开发者）

如果想知道自己车辆的识别效果，可以在电脑上用自己的照片评估（照片只在本机使用，`ocr-samples/` 目录不会提交到代码库）：

1. 把照片放到 `ocr-samples/`，并创建 `ocr-samples/samples.json`，每项写明真实读数和框选区域（照片宽高的比例，左上 x、y，右下 x、y）：

   ```json
   [{ "id": "my-car", "file": "my-car.jpg", "truth": 58320, "category": "clear-digital", "expect": "candidate", "crop": [0.40, 0.55, 0.65, 0.62] }]
   ```

2. 构建并预览：`npm run build`，然后 `npm run preview -- --port 4173`。
3. 另开终端运行 `node scripts/ocr-eval.mjs`，结果打印在终端并写入 `ocr-samples/results.json`。
