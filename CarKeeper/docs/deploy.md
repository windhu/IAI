# 部署与安装

爱车记录是纯静态网页应用，构建产物只有 HTML、JS、CSS、图片和本机识别资源，**不需要服务器程序、数据库或密钥**，也不需要 Android Studio 或 APK。

## 本仓库的 GitHub Pages

根目录的 [部署工作流](../../.github/workflows/deploy-pages.yml) 会将应用发布到
`https://windhu.github.io/IAI/CarKeeper/`，并自动设置 `BASE_PATH`。在仓库 **Settings → Pages** 中选择 **GitHub Actions**，推送到 `main` 后等待工作流完成。站点首页还提供照片水印应用的入口。

## 一、部署到 HTTPS 静态托管

1. 构建：

   ```powershell
   npm install
   npm run build
   ```

   如果网站部署在子目录（例如 `https://example.com/carkeeper/`），构建前设置子目录路径（前后都要有 `/`）：

   ```powershell
   $env:BASE_PATH = '/carkeeper/'; npm run build
   ```

2. 把 `dist/` 目录里的**全部文件**原样上传到静态托管（例如 GitHub Pages、Cloudflare Pages、Netlify、对象存储静态网站等）。

托管要求：

- **必须是 HTTPS**（`localhost` 调试除外）。浏览器只在 HTTPS 下启用离线缓存和“添加到桌面”。
- 保持文件目录结构不变，包括 `sw.js`、`manifest.webmanifest`、`icons/`、`assets/` 和 `ocr/`。
- `ocr/` 下的 `.wasm.js` 和 `.traineddata.gz` 是识别资源，必须能被下载（每台手机只下载其中适合它的一份引擎文件，合计约 6.6 MB，且只在使用拍照识别时下载）。
- 应用使用 `#/` 形式的页面地址，**不需要**配置服务器端路由或重写规则。
- 尽量保持网址不变。浏览器按源（协议、域名和端口）隔离 IndexedDB 数据；更换源或浏览器前请先导出备份，再在新站点恢复。更换路径也会改变 PWA 安装和 service worker 的作用范围，迁移后应重新验证。

发布新版本：重新构建并覆盖上传即可。已打开的用户会看到“有新版本可用”的提示，点“立即更新”后切换；不会自动刷新，也不会清除记录。回滚时同样在**同一网址**上覆盖旧版本文件，不要用清除站点数据的方式回滚。

## 二、在 Android 手机上使用

### 直接用链接

在 **Android Chrome** 中打开网址即可使用全部功能，不安装也可以。

### 添加到桌面

- 如果页面首页“使用与离线”中出现 **安装到桌面** 按钮，点击并确认即可。
- 如果没有这个按钮：点 Chrome 右上角 **⋮** 菜单，选择 **添加到主屏幕** 或 **安装应用**。
- 安装后从桌面图标打开，会以独立窗口运行（没有浏览器地址栏）。
- 部分浏览器或手机系统不提供安装选项，这种情况下继续用链接访问即可，功能相同。

### 离线准备（首次需要联网）

- **第一次打开时必须联网**。页面会在后台缓存应用文件，首页“使用与离线”显示 **已可离线使用** 后，断网也能打开、记录、查看、编辑、删除、导出和恢复备份。
- 如果显示“离线准备未完成”，说明缓存失败，联网状态下依然可以正常使用，可点 **重试**。
- **拍照识别的资源单独下载**（约 6.6 MB）。第一次使用拍照识别时会自动下载，也可以在首页提前点 **下载**。显示“拍照识别资源已就绪”后，断网也能识别。没下载好时断网，识别不可用，但可以手动输入里程，不影响保存。
- 浏览器在存储空间紧张时可能清理缓存或数据，请定期导出备份（见[使用说明](usage.md#备份与恢复)）。

### 数据与隐私

- 记录只保存在手机浏览器的本地数据库中，不会上传。
- 照片只在手机上用于识别，不上传、不保存。
- 应用运行时只会从部署网址下载自身的静态文件和识别资源，不连接其他服务器，没有统计分析。

| 离线记录 | 开启飞行模式，从桌面图标打开，新增、编辑、删除记录 | 全部成功，重新打开后仍在 | 未验证 |
