# Design

## Context

本项目从零开始，与仓库中其他应用隔离；动机和范围见 [proposal.md](proposal.md)。用户希望每天通过邮件查看最多 10 条大连地区案源，自行联系。公开页面不等于获得自动采集或个人信息处理授权；目前没有任何经验证可上线的来源、邮箱或运行环境。

## Goals / Non-Goals

**Goals:**

- 将来源权限、采集结果、线索筛选和发送状态分开，避免不可用来源产生成功形态的空结果。
- 实现可复核的推荐，保留出处和不确定性；第一版无需依赖外部大模型。
- 将手动添加的公开链接和合规自动来源纳入同一处理流程。

**Non-Goals:**

- 不提供自动联系、代理签约、身份信息挖掘、绕过平台限制或成交率预测。
- 不将招聘岗位视为已经确认的外聘需求；不采集私人社交空间和医疗明细。
- 不依赖 GitHub Pages 等纯静态托管实现后台调度。

## Decisions

### 单用户定时任务和持久化存储

采用 Python 单用户命令行程序与 SQLite，使用系统定时器或持续运行的受控主机执行每日批处理，所有时间以 Asia/Shanghai 计算。命令行提供公开链接录入和运行、发送状态查看；第一版不必引入对公网开放的 Web 界面和多用户账户。选择 SQLite 是为了保存去重、运行结果和发送状态，并减少部署负担；纯静态网页无法独立执行定时采集和邮件发送。

单次运行依次执行已启用的来源、规范化与去重、过滤排序、生成摘要、发送邮件。手动链接录入时只保存链接与用户填写的最小摘要；不默认自动请求任意链接，以免访问受限页面、局域网或云实例元数据。若后续增加抓取，必须先验证来源权限并限制协议、域名、重定向及实际解析地址。

### 来源准入和故障隔离

维护来源清单，记录来源类型、地址、核验日期、允许的用途、接入方式和限制；默认禁用未经核验的自动来源。实施时先验证至少一个具体来源对定时检索及本用途的许可，再开发其适配器；无法验证时保持禁用并在状态及邮件中标识，不声称已实现自动案源覆盖。

企业或机构采购、公开求助、招聘分别作为独立来源类别。抖音视频搜索接口存在权限和用途要求，不假定允许后台定时检索；小红书、微信及招聘平台仅在验证合适接口或明确授权后自动接入，其他情况由律师手动提交。每个适配器单独记录成功、失败、零结果或未启用；单个失败不阻断其他来源，但每日摘要须展示失败。

### 线索和排序

线索保存稳定标识、来源类型和链接、发现时间、可证实的发布时间与截止时间、地区、业务标签、需求类别、最小摘要、推荐理由及缺失项。个人不保存身份证、私人联系方式或医疗详情；手动输入同样经过校验和敏感内容处理，无法安全处理时拒绝并提示，而不是存储原文。

按规范化 URL 去重；招聘信息仅在公司和岗位均可可靠匹配时合并，避免将同一企业不同职位合并。过期采购公告排除；地区、时间或需求不明确则标注未知并降低优先级，不凭空推断。用固定、可测试的规则对明确需求、业务地区匹配和时效排序，同条件下明确求助高于招聘弱信号；每条显示规则依据，不输出成交百分比。无条件地按排序取前十会把不相关信息凑入邮件，因此先过滤符合条件的线索再截取。

### 发送和恢复

通过用户配置的邮件服务使用加密连接发送到指定收件人；凭据由运行环境提供，不写入仓库或日志。邮件包含条目、原始链接、未知字段、来源运行状态；纯文本输出或严格转义来源内容。

以本地日期持久记录批次和发送状态；发送确认后才标记成功。进程崩溃或传输中断导致结果未知时标记待确认，提醒用户核验，不自动声称成功或盲目重复发送。明确失败可由用户查看并手动重试，重复运行已确认成功的日期不会再次发送。邮件本身不保证端到端加密，内容保持最小化，部署和备份需要访问控制。

## Risks / Trade-offs

- 来源权限、可用性和线索数量未验证 → 实施前逐项核实并留存依据，未通过的来源默认关闭；邮件中展示覆盖缺口。
- 个人求助可能为旧帖、转发或已有代理人 → 标明发布时间和未知状态，提醒律师自行核实，不保证成交。
- 主机停机或邮件服务不可用 → 持久记录状态，提供可查看的诊断和人工重试；纯邮件无法通知自身的发送故障。
- 线索可能含个人信息 → 最小化存储、限制访问、配置清理期限，核实适用法律及平台规则；不将数据发送给外部 AI 服务。
- 不确定企业与岗位是否重复 → 仅合并有可靠依据的重复项，宁可人工核对也不错误合并。

## Migration Plan

新项目无旧数据迁移。先以测试数据验证筛选及模拟邮件，再核实具体来源权限、配置收件地址和密钥，在受控运行环境启用定时任务。回退时停用定时任务和来源适配器，保留运行状态供核查，并按约定清理线索数据；不影响仓库其他项目。

## Open Questions

- 哪些具体平台和接口能授权本用途、实际有多少大连相关有效线索，需要接入前验证。
- 生产运行主机、邮件服务和推送时刻由部署时配置，不应在方案中假定用户已具备。
