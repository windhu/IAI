# Design

## Context

应用是自包含 HTML：`main` 最大宽度为 720px，预览和控制项纵向排列。预览根据容器宽度、视口高度、照片尺寸及设备像素比计算画布大小，并在窗口尺寸改变时重绘。需求见 [proposal.md](proposal.md) 和 [规格](specs/web-app-delivery/spec.md)。

## Goals / Non-Goals

**Goals:** 在桌面上同时呈现足够大的预览与设置，并确保窄屏和文字放大时仍可使用。

**Non-Goals:** 不更改水印算法、输出文件尺寸或格式，不引入构建步骤、网络资源或依赖。

## Decisions

### 自适应工作区

主容器手机端左右内边距调整为 12px，正文设为浏览器默认字体的 1.0625 倍；桌面最大宽度建议 1100px。在约 960px 及以上的可用视口使用预览与设置双栏，上传入口、状态信息和页面头部保持易于发现；手机及较窄视口使用单栏。栏宽使用可收缩的网格列，并允许长标签、按钮和语言切换器换行。

双栏优于只扩大单列：用户可以同时看到预览和控制项。无需强制铺满超宽屏幕，避免控件过长。

### 预览尺寸与行为

保留当前按容器宽度、视口高度及原图尺寸约束预览的策略，并在工作区改变尺寸时重新计算；若仅靠窗口 `resize` 无法覆盖容器变化，使用浏览器原生尺寸观察并提供兼容处理。保持高分屏渲染、照片宽高比、现有导出分辨率和水印相对位置。避免给画布强设不成比例的 CSS 尺寸。

### 验证

在 360、390、768、1024 和 1440 CSS px 下验证两种语言、默认字体与 200% 字体，检查元素实际边界、触控尺寸及键盘操作。加载横向和纵向照片后切换视口，比较预览与导出的水印相对位置和大小；运行已有布局、国际化测试，并验证单文件直接打开。

## Risks / Trade-offs

- [双栏或大字体挤压预览和控件] → 使用可收缩列、允许换行并在窄屏切回单栏。
- [预览容器变化后画布尺寸过期] → 覆盖窗口和容器变化，测试重绘前后的照片与水印比例。
- [高像素密度或大图导致内存压力] → 保留现有预览约束并测试尺寸变化，不把预览扩大到原图以上。

## Migration Plan

无需数据迁移。提交单文件变更，由现有 Pages 工作流发布；必要时回滚该文件并重新部署。
